# MediaMap

Мониторинг нарушений в медиа Кыргызстана: язык вражды, дезинформация и
цифровое мошенничество. Сообщения подаются публично и попадают в базу после
проверки.

Это новая версия сайта. От прежней взяты структура разделов, тексты и
данные; интерфейс, схема базы и серверная часть написаны заново.

## Запуск

```bash
npm install
npx prisma migrate dev
npm run db:seed
npm run dev
```

Сайт поднимется на `http://localhost:3000`.

Переменные окружения — в `.env`:

```
DATABASE_URL="file:./prisma/dev.db"
SESSION_SECRET="…"
```

## Стек

| Слой | Решение | Почему |
|---|---|---|
| Каркас | Next.js 16, App Router | Серверный рендеринг: страницы нарушений и новостей должны попадать в поиск |
| Стили | Tailwind CSS 4 | Токены задаются в CSS, отдельного конфига нет |
| База | Prisma 7 + SQLite | На сервере переедет на Postgres, схема к этому готова |
| Шрифты | Geologica, Golos Text, JetBrains Mono | Кириллические по происхождению — важно для кыргызского |

## Устройство

```
prisma/

  seed.ts            наполнение из seed-data.json
scripts/

```

## Дизайн-система

Все цвета и размеры живут в `src/app/globals.css`. Правило простое: если
нужного значения нет в токенах, решение ещё не принято — принимать его надо
там, а не дописывать число в разметке.

Контраст палитры проверяется скриптом:

```bash
npm run check:contrast
```

Замеры на главной: текста мельче 12px нет, начертаний два, цветов текста
пять, провалов контраста нет, на 375px нет горизонтальной прокрутки, все
цели нажатия от 24px.

## Аккаунты заявителей

Дело добровольное. Анонимная подача остаётся основным путём и работает без
всякого аккаунта — это не удобство, а защита: люди жалуются на соседей и на
местных чиновников, и база «кто на кого пожаловался» была бы мишенью.

Аккаунт даёт одно: сообщения видны на любом устройстве, а не только в том
браузере, откуда их подали. Без аккаунта работает ключ в localStorage.

Три способа входа: почта с паролем, Google, Facebook. Роль у всех
зарегистрировавшихся — REPORTER, в панель она не пускает.

### Ключи для Google и Facebook

В коде их нет — репозиторий публичный. Пока переменные не заданы, кнопки
просто не показываются, и сайт не обещает того, чего не умеет.

```
SITE_URL=https://ваш-домен
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
FACEBOOK_CLIENT_ID=...
FACEBOOK_CLIENT_SECRET=...
```

Где взять: Google — консоль Google Cloud, раздел OAuth 2.0 Client IDs.
Facebook — Meta for Developers, приложение с продуктом Facebook Login.
В обоих нужно прописать адрес возврата:

```
https://ваш-домен/api/auth/google/callback
https://ваш-домен/api/auth/facebook/callback
```

`SITE_URL` обязателен: адрес возврата берётся из него, а не из заголовков
запроса — иначе его можно подменить чужим доменом.

## Панель сотрудника

Живёт на `/admin`, отдельно от сайта: свой каркас, без публичной шапки,
закрыта от индексации, одноязычная.

Первый сотрудник заводится скриптом. Пароль передаётся переменной
окружения, а не аргументом — иначе он останется в истории команд:

```bash
ADMIN_EMAIL=you@example.kg ADMIN_PASSWORD='...' npm run admin:create
```

Повторный запуск с тем же адресом меняет пароль. Пока нет восстановления
доступа, это же и способ его сбросить.

В панели два раздела. **Очередь** — непроверенные сообщения, отсортированы
по убыванию уверенности разбора: сверху самое похожее на настоящее
нарушение, внизу бессмыслица. Кнопки подтверждают или отклоняют, заметка
необязательна. **Тексты сайта** — правка любой строки на обоих языках.

Сессия лежит в базе, а не в самоподписанном токене: доступ можно отозвать,
не заставляя менять пароль. Кука httpOnly, живёт две недели.

## Предварительная оценка сообщений

Сообщение при подаче получает оценку: вероятный вид нарушения, уверенность
и перечень признаков, из которых сложился вывод. Оценка ничего не решает —
статус ставит человек, — она нужна, чтобы очередь на проверку шла с самого
похожего на настоящее нарушение.

Сейчас оценку даёт разбор по ключевым словам (`src/server/ai-review.ts`).
Языковой модели там намеренно нет: заглушка со случайными процентами
выглядела бы убедительно, а за числами не стояло бы ничего. Разбор по
словам примитивен, зато каждое число объяснимо, и человеку показывается,
за что оно получено.

Когда подключим модель, меняется одна функция — `assess`. Поле `aiSource`
в базе говорит, чем снята оценка (`rules` или `model`), иначе через полгода
не понять, чему верить в старых записях.

## Если после миграции всё падает в 500

Dev-сервер держит сгенерированный клиент Prisma в памяти. После
`prisma migrate` и `prisma generate` его надо перезапустить — на диске
клиент уже новый, а в процессе старый. Симптом узнаваемый:
`no such column` или `Unknown argument` про колонку, которую вы только что
добавили. Ошибка не в коде.

## Языки

Язык живёт в адресе: `/ru/...`, `/ky/...`. Так каждая версия — отдельная
страница, которую можно переслать, сохранить в закладки и проиндексировать
поиском.

Готовы русский и кыргызский. Английский, узбекский и казахский стоят в
переключателе заглушками с пометкой «скоро»: их видно, но выбрать нельзя,
пока нет перевода. Обращение к неготовому языку уводит на русскую версию.

Словари лежат по файлу на язык в `src/lib/i18n/`. Кыргызский типизирован
через русский, поэтому забытый ключ станет ошибкой сборки, а не пустым
местом на странице.

## Приложенные файлы

К сообщению можно приложить до пяти файлов: изображения до 8 МБ, видео до
32 МБ, всё вместе до 48 МБ. Потолки заданы в `src/lib/attachment-rules.ts`
и оттуда же попадают в `next.config.ts` и в тексты ошибок — менять их надо
в одном месте.

Файлы лежат в папке `uploads/` рядом с проектом, не в `public`. Из `public`
их раздавал бы Next, никого не спрашивая, и снимок из ещё не рассмотренного
сообщения был бы открыт любому. Раздаёт их `/api/attachments/[id]`: всем —
если случай опубликован, подавшему — по личному ключу в `?t=`, сотруднику —
всегда.

Переезд на внешнее хранилище (R2, S3) — это переписать `src/server/storage.ts`.
Снаружи ключ хранилища никто не разбирает, для остального кода это строка.

Тип файла берётся из заголовка, а не из расширения имени, и сверяется с
белым списком. Имя, с которым файл пришёл, показывается человеку, но путь
из него не строится — на диске у файла случайное имя.

## Ограничение частоты отправки

Пять сообщений в час с одного адреса, `src/server/rate-limit.ts`. Считается
в памяти, и хранится не адрес, а его отпечаток с солью, новой на каждый
запуск: сайт обещает анонимность, а таблица «кто и когда отправлял» этому
обещанию противоречит.

Чем платим: счётчик обнуляется при перезапуске, и на нескольких копиях
приложения у каждой он свой. От человека, который в сердцах жмёт кнопку,
этого хватает; против настоящего напора нужен общий счётчик или защита на
входе в сервер.

## Почему нет карты

Карта была дважды и оба раза не прижилась. Сначала областями — заказчик
уточнил, что привязка к месту у случаев редкая. Потом тепловым полем — но у
всех 65 подтверждённых случаев разные точки, самая «горячая» из них десять
случаев, и вместо плотности выходил ровный налёт.

Взамен на главной ничего не стоит. Пустое место честнее графика ни о чём.

Вместе с картой убраны `three.js`, `d3-geo`, геометрия границ и своя
проекция Меркатора. От `kg-map.ts` остался список кодов областей —
`src/lib/regions.ts`, он нужен для проверки поля формы.

## Что ещё не сделано

Оценку сообщений даёт разбор по ключевым словам, а не языковая модель —
см. раздел про предварительную оценку.

Письмом о решении не сообщаем: контактов у анонимного заявителя нет.

База на SQLite, на сервере нужен Postgres. Колонки те же.

Кыргызские строки в `src/lib/i18n/ky.ts` нуждаются в вычитке носителем языка.
