# Временный стенд: Vercel + Turso + R2

Документ про **временную** площадку — показать сайт, пока нет своего
сервера. Постоянное место описано в [deploy.md](deploy.md); здесь другое,
и уезжать отсюда придётся.

## Что здесь работает, а что нет

| | |
|---|---|
| Сайт, случаи, аналитика, поиск, глоссарий | работает |
| Подача сообщений, аккаунты, панель | работает |
| Вложения | **только до 4 МБ** — см. ниже |
| Разбор моделью | падает на разбор по ключевым словам |
| Перевод новостей | **не работает** |
| Ограничение частоты подач | **фактически не работает** |

**Вложения до 4 МБ.** У Vercel потолок тела запроса 4,5 МБ, это
ограничение площадки, настройками не снимается: всё сверх обрывается с
ошибкой 413. Поэтому лимиты в `src/lib/attachment-rules.ts` снижены с 8 и
32 МБ до 4. Снимок экрана с телефона проходит почти всегда, запись экрана
почти никогда. На своём сервере числа возвращаются к прежним, и больше
менять ничего не нужно — `next.config.ts` берёт потолок оттуда же.

Снять это можно только загрузкой из браузера прямо в R2, мимо Vercel. Это
переделка формы, и в этот документ она не входит.

**Перевод не работает** и работать не будет: NLLB держит в памяти три
гигабайта и грузится двадцать секунд, а на Vercel нет ни того, ни другого.

**Ограничение частоты подач** считается в памяти процесса (см.
`src/server/rate-limit.ts`, там объяснено, почему не в базе: счётчик в
базе — это журнал обращений с привязкой к адресу, а сайт обещает
анонимность). На Vercel процессов много и они эфемерны, поэтому счётчик у
каждого свой и предел умножается. Для показа заказчику терпимо, для
открытого приёма сообщений — нет.

## 1. База: Turso

Файла базы на Vercel не бывает — файловая система между запусками не
живёт. Код к этому готов: он ходит через `@prisma/adapter-libsql`, а тот
умеет удалённый libsql.

```bash
# на своей машине
curl -sSfL https://get.tur.so/install.sh | bash
turso auth signup
turso db create mediamap
turso db show mediamap --url        # libsql://mediamap-….turso.io
turso db tokens create mediamap     # длинная строка
```

Накатить миграции. Команды миграции токен из переменной не читают, поэтому
здесь — и только здесь — он приписывается к адресу:

```bash
DATABASE_URL="libsql://mediamap-….turso.io?authToken=ТОКЕН" \
  npx prisma migrate deploy
```

Проверить, что таблицы на месте:

```bash
turso db shell mediamap ".tables"
```

## 2. Вложения: ведро R2

Cloudflare → R2 → Create bucket, имя `mediamap`. Регион любой.

Затем **Manage R2 API Tokens** → Create API token → права Object Read &
Write, только на это ведро. Записать три значения: Access Key ID, Secret
Access Key и Account ID (он виден в адресе панели Cloudflare).

Ведро оставить закрытым. Публичный доступ включать не надо: файлы раздаёт
наш обработчик `/api/attachments/[id]`, он же решает, кому можно. Снимок
из ещё не рассмотренного сообщения открытым быть не должен.

## 3. Vercel

Import Project → репозиторий → Framework Next.js (определится сам).

Переменные окружения (Settings → Environment Variables):

```
DATABASE_URL           libsql://mediamap-….turso.io
DATABASE_AUTH_TOKEN    <токен из turso db tokens create>
SITE_URL               https://<имя>.vercel.app
R2_ACCOUNT_ID          <из панели Cloudflare>
R2_ACCESS_KEY_ID       <из токена R2>
R2_SECRET_ACCESS_KEY   <из токена R2>
R2_BUCKET              mediamap
```

`ML_SERVICE_URL` **оставить пустым**. Пустой он выключает и разбор
моделью, и перевод — сайт про это знает и работает дальше. Указать сюда
адрес своего ML-сервиса нельзя: у сервиса нет ни пароля, ни счётчика
запросов, и открытый наружу он означает, что ваш ключ OpenAI тратит кто
угодно.

`SITE_URL` заполнить обязательно. Сайт при пустом или локальном адресе не
поднимется намеренно: без него вход через Google уводит на localhost, а в
письмах заявителям стоят нерабочие ссылки — ошибка тихая, поэтому она
сделана громкой.

Сборка идёт командой `prisma generate && next build`. Строка уже в
`package.json`: клиент Prisma лежит в `src/generated/`, эта папка в
`.gitignore`, и без генерации сборка на чистой машине падает.

## 4. Первый администратор

`npm run admin:create` на Vercel не запустить — там нет консоли. С своей
машины, указав ту же базу:

```bash
DATABASE_URL="libsql://mediamap-….turso.io?authToken=ТОКЕН" \
  ADMIN_EMAIL=you@example.kg ADMIN_PASSWORD='…' npm run admin:create
```

## 5. Проверка

```bash
curl -sI https://<имя>.vercel.app/ru | head -1     # 200
```

Руками: открыть `/ru`, подать сообщение с картинкой меньше 4 МБ, войти в
`/admin/login`, убедиться, что сообщение видно и снимок открывается. Если
снимок не открывается — почти всегда дело в ключах R2: заполнены не все
четыре, и код честно считает, что ведра нет, и пишет на диск, которого
там нет.

## Переезд обратно

Ничего не теряется и переносится по [deploy.md](deploy.md):

1. Выгрузить базу: `turso db shell mediamap .dump > mediamap.sql`,
   влить в `prisma/dev.db` на сервере.
2. Скачать вложения из ведра в `uploads/` (`rclone` или панель R2).
3. Убрать из `.env` четыре ключа R2 и `DATABASE_AUTH_TOKEN` — код сам
   вернётся к файлу и папке.
4. Вернуть лимиты в `src/lib/attachment-rules.ts` к 8 и 32 МБ.
