# Выкладка: тестовый и демонстрационный стенд

Документ описывает первый этап — стенд, на котором можно показать работу
заказчику и погонять её руками. Он не про промышленную эксплуатацию: про то,
чего в нём нет, честно сказано в конце.

## Куда выкладывать и почему

**Одна виртуальная машина: 4 ядра, 8 ГБ памяти, от 40 ГБ диска.** Все три
части — сайт, ML-сервис и база — живут на ней рядом.

Так решено из-за ML-сервиса. Модель перевода NLLB держит в памяти **около
трёх гигабайт** и грузится двадцать секунд; выгружать её между запросами
нельзя, иначе каждый перевод начинается с этих двадцати секунд. Это сразу
отсекает всё, что рассчитано на короткие запуски.

**Провайдер — Hetzner, тариф CPX31** (4 ядра, 8 ГБ, 160 ГБ). Ориентировочно
18-25 долларов в месяц; цены там в 2026 году поднимали, так что проверьте
перед заказом. Тариф CX32, который был вдвое дешевле, закрыт для новых
заказов.

Причина не в цене. **Cobalt уже работает у Hetzner** (`95.216.169.56`), а
ML-сервис ходит к нему на каждой заявке со ссылкой. Один провайдер — это
внутренняя сеть вместо интернета, один счёт и одна учётная запись, которая
у вас уже заведена и проверена. Если на машине с Cobalt свободно 5 ГБ
памяти и 10 ГБ диска, вторую можно вообще не заводить.

### Если Hetzner не подходит

**Netcup, тариф VPS 3000 G11** — 6 ядер, 8 ГБ, 256 ГБ, около 10 евро.
Германия, EU, приличные ядра. Разумная замена, если не хочется возвращаться
к Hetzner.

**Contabo за 7 долларов брать не советую.** Дёшево из-за слабых ядер и
обычного SSD вместо NVMe. Нам это дорого выйдет: перевод и разбор снимков
считаются на процессоре, и там, где сейчас уходит секунда, будет три. Плюс
медленная поддержка — плохое качество для стенда, который показывают
заказчику.

**DigitalOcean и Vultr** просят 40-48 долларов за ту же конфигурацию. Платят
за удобную панель; для гранта это тяжело обосновать.

**Россию (Timeweb, Selectel) не рассматриваю.** Проект финансируется по линии
ЕС и собирает сообщения о нарушениях в медиа — юрисдикция хранения тут не
формальность.

Задержка из Кыргызстана до Европы около 100 мс. Для стенда это незаметно.

### Что считали

| | Диск | Память в работе |
|---|---|---|
| Сайт (`node_modules` + сборка) | 1,2 ГБ | ~0,5 ГБ |
| ML-сервис (`.venv` + модель NLLB) | 3,7 ГБ | ~3 ГБ |
| База и вложения | растёт медленно | — |

Восьми гигабайт хватает с запасом: сборка сайта на сервере просит около двух
гигабайт разово, и на четырёх она уже упирается.

### Чего не выбрали

**Vercel** не берёт ML-сервис: там нет ни трёх гигабайт памяти, ни
постоянного процесса. Вложения он тоже теряет — файловая система пропадает
между запусками, пришлось бы заводить объектное хранилище. То есть один
сервер всё равно понадобился бы, только к нему добавилась бы вторая
площадка.

**Railway, Render, Fly** это умеют, но тариф с четырьмя гигабайтами памяти
стоит дороже такой же машины, а образ с моделью на 2,4 ГБ надо либо
пересобирать при каждой выкладке, либо держать в томе. Для демонстрации это
лишние движущиеся части.

## База: пока SQLite

На демо-стенде база — файл `prisma/dev.db` рядом с проектом. Отдельной службы
нет, резервная копия — это `cp`.

В схеме написано, что на сервере будет Postgres, и это правильно: SQLite
пишет по одному, и при десятке одновременных подач очередь на запись станет
заметна. Но на стенде, где сообщения подают вручную, разница нулевая, а
Postgres — это ещё одна служба, ещё один пароль и ещё один способ уронить
демонстрацию. Переезд отложен осознанно; что для него нужно, написано ниже.

## Порядок действий

Ниже `mediamap.kg` замените на свой домен, а `mediamap` — на имя
пользователя, от которого всё работает.

### 1. Машина и пользователь

```bash
adduser --system --group --home /srv/mediamap mediamap
apt update && apt install -y git curl caddy
curl -fsSL https://deb.nodesource.com/setup_22.x | bash - && apt install -y nodejs
apt install -y python3.12 python3.12-venv
```

### 2. Код

```bash
mkdir -p /srv/mediamap && cd /srv/mediamap
git clone https://github.com/janatlk/mediamap_web.git web
git clone <адрес репозитория ML-сервиса> ml
chown -R mediamap:mediamap /srv/mediamap
```

### 3. Сайт

```bash
cd /srv/mediamap/web
cp .env.example .env      # заполнить: SITE_URL обязательно
npm ci
npx prisma migrate deploy
npx prisma generate
npm run build
mkdir -p uploads
```

Сайт при запуске сам проверяет `SITE_URL` и не поднимется с пустым или
локальным адресом: без него вход через Google уводит на localhost, а в
письмах заявителям стоят нерабочие ссылки — ошибка тихая, поэтому она
сделана громкой.

### 4. ML-сервис

```bash
cd /srv/mediamap/ml
cp .env.example .env      # заполнить: LLM_API_KEY, BRAVE_API_KEY, COBALT_*
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt

# Модель перевода: 2,4 ГБ. Тянем заранее — иначе первый человек,
# нажавший «перевести», будет ждать эти гигабайты.
HF_HOME=/srv/mediamap/ml/.cache .venv/bin/python scripts/fetch_translator.py
```

### 5. Службы и прокси

```bash
cp /srv/mediamap/web/deploy/mediamap-*.service /etc/systemd/system/
cp /srv/mediamap/web/deploy/Caddyfile /etc/caddy/Caddyfile   # поправить домен
systemctl daemon-reload
systemctl enable --now mediamap-ml mediamap-web
systemctl reload caddy
```

Проверка:

```bash
curl -s localhost:8000/health          # ML-сервис
curl -si localhost:3000/ru | head -1   # сайт
journalctl -u mediamap-web -n 20       # что сказал при старте
```

### 6. Первый администратор

```bash
cd /srv/mediamap/web && npm run admin:create
```

### 7. Вход через Google

В консоли Google в разрешённые адреса возврата добавить
`https://mediamap.kg/api/auth/google/callback`. Без этого кнопка входа
приведёт на ошибку Google, а не на сайт.

## Что важно не забыть

**Оба сервиса слушают только `127.0.0.1`.** Наружу пускает Caddy — он же
держит сертификат. У сайта адрес задан флагом `-H`, а не переменной
`HOSTNAME`: Next 16 её не смотрит, и с ней сервер поднимается на всех
интерфейсах.

**У ML-сервиса это особенно важно.** У него нет ни пароля, ни счётчика
запросов: кто до него дотянется, тот тратит ваш ключ OpenAI. В systemd-файле
это задано явно; если будете запускать руками — не поставьте туда `0.0.0.0`.

**Резервная копия — два места:** файл базы `prisma/dev.db` и папка
`uploads/`. Вложения не восстановить ниоткуда: публикацию, о которой сообщил
заявитель, к моменту проверки часто уже удаляют, и снимок остаётся
единственным свидетельством.

```bash
# в cron, ежедневно
tar czf /var/backups/mediamap-$(date +%F).tgz \
    /srv/mediamap/web/prisma/dev.db /srv/mediamap/web/uploads
```

**Ключи от OpenAI и Brave живут только в `.env` на сервере.** В git их нет и
быть не должно.

## Чего в этом стенде нет

Перечислено не для галочки: каждый пункт когда-нибудь всплывёт.

**Postgres.** Пока SQLite. Переезд — это адаптер в `src/lib/db.ts`, новая
строка `DATABASE_URL` и пересборка миграций: нынешние написаны под SQLite и
на Postgres не наложатся.

**Второй экземпляр сайта.** Ограничение частоты подачи считается в памяти
процесса. Запустите два — счётчик у каждого будет свой, и предел удвоится.
Для одного экземпляра это работает как задумано.

**Автоматическая выкладка.** Обновление руками: `git pull`, `npm ci`,
`npm run build`, `systemctl restart`. Для демонстрации достаточно.

**Почта.** Извещения заявителям написаны и проверены, но без `SMTP_HOST`
письма не уходят — молча, со строкой в журнале.

**Разбор длинного видео.** Ссылки на Instagram, TikTok и Facebook идут через
Cobalt, и расшифровка речи занимает больше двух минут — дольше, чем сайт
готов ждать. Такие заявки откатываются на разбор описания и честно об этом
пишут.
